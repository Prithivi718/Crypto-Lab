# 2. EXACT RESPONSIBILITY OF EACH SERVICE

## `crypto.service.js`

Responsible only for actual cryptographic operations.

Examples:

```text
generateEdKeys()
keyExchange()
deriveSessionKey()
generateRSAKeys()
wrapSessionKey()
encryptMessage()
createSignedData()
signEd25519()
verifyEd25519()
unwrapSessionKey()
decryptMessage()
```

It must not:

* create reports
* generate benchmark summaries
* manage HTTP
* control page navigation
* render UI
* generate human-readable final reports

It performs cryptographic work and returns the necessary raw results.

# 3. `workflow.service.js`

Purpose:

> Provide the user with a deep, step-by-step demonstration of the entire cryptographic pipeline.

Workflow is educational.

It must execute one step at a time and return information needed by the Pipeline UI.

The user can see:

```text
01 Ed25519
02 ECDH
03 HKDF
04 RSA-OAEP
05 AES-256-GCM
06 Packet Signing
07 Signature Verification
08 RSA Session Key Recovery
09 AES-256-GCM Decryption
```

The workflow service must maintain an execution context throughout the complete workflow.

The workflow service must NOT calculate benchmark summaries.

It may measure each operation's duration using the shared timing utilities so that telemetry can be shown in the Pipeline UI.

# 4. `process.service.js`

Purpose:

> Execute the complete encryption + decryption + verification process in one call.

This corresponds to the Mission page's:


The current `process.service.js` already follows this general encryption → decryption → comparison flow and should be refactored rather than replaced unnecessarily.  

Remove any direct test invocation from the bottom of the service such as:

A service module must not execute itself merely because it is imported.

# 7. EXECUTION CONTEXT LIFECYCLE

When a user starts an execution:

```text
createExecutionContext()
```

The context receives a unique `executionId`.

Example:

```text
exec-1728439201
```

Then Workflow or Process modifies that same execution context during execution.

Do not create a separate context for every cryptographic operation.

For:

```text
"Thanks a lot GPT"
```

there must be one execution context covering:

```text
Ed25519 → ECDH → HKDF → RSA → AES → Sign → Verify → Unwrap → Decrypt
```

Encryption and decryption belong to the same execution.

# 20. SENSITIVE-DATA MASKING UTILITY

Create:

```text
src/utils/maskSensitive.js
```

Provide:

```js
maskSensitive(value, options)
```

Default behavior:

```text
visible characters = 4
mask character = *
```

Example:

```text
abcdef1234567890
```

becomes:

```text
abcd********
```

Do not use:

```text
abcd...
```

The mask must use literal `*` characters.

The utility should work with:

* strings
* Buffer
* Uint8Array
* ArrayBuffer
* serialized cryptographic values

Normalize the input safely before masking.

Do not alter the actual stored value.

The utility should make it possible to obtain:

```js
{
    raw: originalValue,
    display: maskedValue
}
```

where appropriate internally.
