8. FILE UPLOAD CORE
============================================================

Create/complete:

uploadController.js
uploadRoutes.js

The purpose is to let the frontend upload:

message.txt

The content of the uploaded file becomes the confidential plaintext.

Example:

message.txt

TOP SECRET:
Mission Alpha.
Deliver package at 0300 hrs.

The backend must:

1. Receive multipart/form-data.
2. Validate that a file exists.
3. Ensure file type/extension is permitted.
4. Ensure file size is within limits.
5. Read the text content.
6. Return the extracted plaintext or initialize workflow with it.
7. Remove temporary uploaded file after the content is read.
8. Never pass the file object directly into crypto.service.js.

The crypto layer should receive:

message = file contents

not:

message = filename

22. COMPLETE BACKEND FLOW
============================================================

The finished backend should allow this:

USER
 ↓
Uploads message.txt
 ↓
POST /api/upload
 ↓
Multer
 ↓
uploadController
 ↓
fileUtils
 ↓
plaintext extracted
 ↓
POST /api/workflow/start
 ↓
workflow.service initializes state
 ↓
workflowId returned
 ↓
FRONTEND
 ↓
user clicks NEXT
 ↓
POST /api/workflow/step
 ↓
workflowController
 ↓
workflow.service
 ↓
crypto.service.js
 ↓
one algorithm executes
 ↓
result stored in workflow state
 ↓
safe step result returned
 ↓
frontend displays it
 ↓
user clicks NEXT
 ↓
repeat

And if the user clicks the whole process written in the process.service.js, to execute complete algorithm
Build the backend so the Workflow is used only for step-by-step educational explanation and execution navigation, 
showing what each algorithm does and how the cryptographic process progresses, without detailed benchmarking or 
performance metrics. The Process service should execute the complete encryption → packet/authentication → decryption pipeline 
in one run and produce the complete raw execution result. 
After the process finishes, create a separate Output/Analysis result layer that consumes the completed process
result and presents measurable metrics such as input filename, file size, plaintext content size in bytes, 
ciphertext size, key/parameter sizes, per-algorithm execution time, total encryption time, total decryption time, 
and overall execution time. The final output should clearly show authentication/signature verification, integrity 
verification, original vs recovered message, and whether the complete process passed or failed. Keep sensitive 
cryptographic material masked while exposing safe metrics and representations suitable for charts, tables, and 
project presentation. 
This output layer should be independent from workflow.service.js so the workflow remains clean and 
focused on explaining the cryptographic process.
