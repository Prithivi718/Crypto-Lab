1. Clicking a navbar link

When the user clicks a navigation link:

Do not reload the page.
Smoothly scroll to the corresponding section.
The target section should be positioned correctly below the fixed/sticky navbar so its heading/content isn't hidden behind the navbar.
The clicked navigation link should immediately become the active navigation item.
The active link should be visually indicated using the existing underline/accent-line styling.

     ─────
      ACTIVE

If the user clicks Cryptographic Pipeline:

Mission Ingest       Cryptographic Pipeline       System Benchmark
                          ─────────────────
                               ACTIVE
2. Scrolling manually

The active navigation state must also update automatically when the user scrolls manually.

As the user scrolls down through the page:

Detect which major section is currently in the viewport.
Update the corresponding navbar link to the active state.
Remove the active styling from the previously active link.
Apply the underline/accent indicator to the navigation link associated with the section currently being viewed.

Therefore, the navbar should always communicate:

"You are currently here."

For example:

┌─────────────────────────────────────────────────────────┐

│                    ─────────────────                     │
└─────────────────────────────────────────────────────────┘
3. Use Intersection Observer

Prefer using IntersectionObserver rather than constantly listening to the scroll event.

Configure it so that a section becomes active when a meaningful portion of that section enters the viewport.

Avoid rapid flickering when two sections are simultaneously visible. There should always be one clearly active navigation item.

4. Navbar behavior

The navbar is fixed/sticky at the top of the page.

Make sure the scroll target accounts for the navbar height.

Use CSS such as:

html {
  scroll-behavior: smooth;
}

section {
  scroll-margin-top: 80px;
}

Adjust 80px according to the actual navbar height rather than blindly using this value.

Preserve the existing SecureNet visual language and styling.

Only add the necessary active-state behavior:

.nav-link.active {

}

The active state should use the existing green/olive accent and underline rather than introducing a new color or visual treatment.

6. Important behavior

The navigation state must work in both directions:

Scroll down → active section updates.
Scroll up → active section updates.
Click navbar link → smooth scroll + active state updates.
Continue scrolling after clicking → active state continues updating naturally.

Do not hardcode the active link based only on click events.

The section currently visible in the viewport must ultimately determine the active navigation state.
